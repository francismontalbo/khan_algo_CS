FINAL EDITION · 15 OCTOBER 2026

Verification and research boundaries

The final edition retains the comparison tools, source records, tree, proofs, glossary, lessons, simulations and real-use examples. It is ready for study and for designing the initial thesis pilot within the limits below.

This is not a novelty certificate. The simulations establish neither a real Montage speedup nor independent confirmation of every published result. Full benchmark inputs and a fair experiment are still needed.

Corrections in this edition

The fresh-start comparison now explains Kahn and priority selection first. Controls have clearer focus and mobile spacing, closing a definition preserves the underlying example, and exports retain the final styling. The Kahn calculation now highlights the state-changing code line rather than its neighboring operation counter.

Record E34 now identifies LATTICE version 3 and retains the older DAN-Scheduler title as version history. The current authors and abstract were checked; the original full-text assessment must not be transferred silently to the revised paper.

Source checks

These are targeted finishing checks, not a new exhaustive search. Existing access levels and study-family distinctions remain in the source records.

  • E34 — Primary abstract, author list and submission history. Full v3 methods and results not reproduced. The version-specific URL produced a cache miss in the retrieval tool; the base arXiv page explicitly identifies current version v3.
  • E29 — Official commit metadata and diff retrieved through GitHub. The unchanged-schedule statement is an author claim; no local compiler benchmark.
  • foundation — Official documentation. No separate CPython implementation regression test performed.
  • Horizons — Primary full HTML and metadata. Published performance is not independently reproduced.
  • Dask — Official ordering documentation. Not a claim that Dask exactly implements the local priority model.
  • Montage metadata — Official directory and retained repository documentation. Complete selected trace bytes and real Montage timing runs not available here.
  • MoSAIC — Indexed primary abstract. The complete paper and implementation were not audited during this final pass.

What was not verified

Full external recordings and playback, all possible comparison pairs, Firefox, Safari, physical devices, and the complete revised methods for abstract-only records were not tested. File-origin navigation was blocked by the verification environment; interaction checks loaded the local HTML contents. No server or external script is required by the guide itself.

Use the evidence correctly

Keep author-reported results separate from local tests. Distinguish real software adoption from an illustrative input. Related versions are one study family. A blank comparison field is missing evidence, not proof of an untouched research gap.

For the BSCS thesis, investigate one student-designed change, define the invariant it must preserve, and measure total order-construction time with preprocessing included. Counter operations may explain the result but do not substitute for runtime evidence.

Reproduce and preserve

Run python verify.py with Python, Node.js and NetworkX. Detailed logs and code are in the package; historical screenshots are preserved in the reference archive under assets/final. Export notes before moving the guide. Read README.md to open the guide and TESTING.md for maintainer setup and current report paths.
