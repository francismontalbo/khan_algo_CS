Terms and nomenclature

Reference for the workflow comparison. Select a term for its explanation, example, cautions and sources.

Symbols follow the included teaching model. A source paper or code version may use the same letter differently. Read its definitions before comparing bounds.

Concepts

TermMeaningUse in this guide
AblationAn experiment that isolates one mechanismRemove or vary one component while holding the rest fixed.
Affected intervalA positional region involved in order repairIn incremental ordering, a dependency insertion can require revising part of the existing order.
AggregationCombining repeated bookkeepingRepresent identical consumer sets with shared state and a combined byte weight.
The setup can cost more than the repeated work it saves.
AliasingSeveral names or values refer to the same storageDistinct values can share physical storage.
The local immutable-file model excludes aliases. Summing apparent value sizes can double-count shared storage.
Amortized costAverage charged cost across a sequence of operationsAn accounting guarantee over the sequence, not an average over random trials.
One operation can cost more than the amortized bound.
AncestorA vertex earlier along a directed pathAn ancestor can reach the current vertex through one or more edges.
ArrayA sequence accessed by positionUse an integer index to locate an element.
Contiguous layout and cache behavior affect real performance; the word array alone is not a speed guarantee.
Auxiliary spaceMemory used in addition to the supplied inputCounters, queues, indexes and other working state.
State whether the graph itself is counted and whether stale heap entries are included.
Average memoryMemory use averaged over an execution intervalAn objective distinct from the maximum at a single instant.
Equal task-order peaks do not imply equal average memory, especially when runtimes differ.
AWS LambdaAWS service for running function codeA function execution service in related Montage experiments.
BaselineA comparison method under matched conditionsThe reference against which an improvement is evaluated.
A slower language or avoidable implementation defect can create a misleading speedup.
BenchmarkA defined workload and measurement procedureInputs plus a fair, reproducible method of evaluation.
Repeated timing runs are not new independent workflow instances.
Break-even pointWhere added preparation equals the work it savesA method helps only after its benefits outweigh its full overhead.
Do not manufacture repeated recomputation when an application could reuse its existing order.
BufferStorage holding an intermediate valueIn the compiler, a memory object used by one or more operations.
A compiler buffer and a workflow file are analogous for some counting rules, but not interchangeable in all memory semantics.
CacheStorage used to reuse previously obtained dataA cache can avoid repeating expensive loads or computations.
Hardware caches, operating-system page caches and application caches are different layers.
CleanupRemoval of files that are no longer requiredA workflow-management operation with its own dependency and cost rules.
The priority-counter reductions are not a replacement for a fully correct cleanup engine.
Cloud computingOn-demand computing servicesRemote execution resources provided as a service.
ClusterMultiple computers used togetherTasks may be assigned to separate machines.
Network transfers and placement effects do not occur in the same way in a one-process metadata replay.
CommitA recorded source-code revisionIdentifies a particular version and its parent in version control.
A commit message states the authors’ intent; it is not an independently measured benchmark.
CompilerSoftware that translates and optimizes a programIt turns a higher-level representation into a form suitable for execution.
ConfounderAnother factor that could explain an observed differenceFor example, changing data structures and the decision rule at the same time.
ConsumerA task that uses a file or bufferThe user of an intermediate result.
Consumer setIdentities of all tasks using a fileA set of users, not merely their number.
Control dependencyAn ordering constraint apart from data useAn operation must wait for another even when it does not consume that operation’s value.
Ignoring control dependencies can make a schedule invalid.
Correctness oracleAn independently computed reference answerA slower direct method used to check a faster implementation.
An oracle can still contain bugs. Use structural validity checks and counterexamples as well.
CounterexampleOne valid case that refutes a universal claimIt can show that a heuristic is not always optimal.
Coverage conditionEvery removed consumer precedes a retained consumerThe correctness condition for the local consumer-reduction proof.
The guarantee concerns ready-task scores, not equality of all internal counters.
Critical pathA dependency path constraining completion timeUnder fixed task durations, a longest-duration prerequisite path provides a lower bound on completion time.
Resource and communication constraints can make actual makespan longer.
DaskPython task-graph computing systemExecutes dependent computations and applies scheduling policies.
Its distributed execution policies are not identical to the local sequential storage-score model.
Data footprintAmount of data retained during executionA study-specific measure of stored or live data.
Check whether a source measures files, buffers, process memory, or staged data before comparing values.
Data stagingMoving input or output data to the execution sitePreparation or transfer work performed around a task.
DataflowHow values move between operationsProducer-to-consumer relationships in a computation.
Control dependencies can constrain execution even when they do not transfer a data value.
Dense indexingMap objects to consecutive integer IDsReplace repeated object-key lookups with array positions.
Indexing changes representation, not the task-priority objective. Creating the mapping also costs work.
Dependency certificateA checkable reason that a reduction is safeIn the teaching search, an actual path showing one consumer must precede another.
DescendantA vertex later along a directed pathA descendant is reachable through one or more directed edges.
DeterministicSame inputs and rules give the same resultThe intended order comparison uses fixed ties and no random choice.
Directed cycleA directed path returning to its startA dependency cycle prevents a complete topological order.
EdgeA directed dependency linkAn edge u → v requires u to precede v.
EnumerationGenerating all members of a solution setHere, generating all valid topological orders.
A graph can have extremely many valid orders. Cheap work per output does not imply cheap total enumeration.
EvictionRemoving an item from a cache or limited memoryFrees capacity under a policy.
Evicting data that can be reloaded is different from permanently deleting a file after final use.
Evidence levelHow closely a source has been inspectedFull code, full text, abstract only and local tests establish different things.
Exact methodA method with an explicitly exact targetIt may find an optimum or preserve a stated reference result; specify which.
Exact equivalence to a greedy policy is not exact optimization of peak memory.
Execution modelAssumptions about how tasks and files behaveThe rules under which the algorithm’s guarantee is stated.
A guarantee may fail when retries, aliasing or parallel completion are added.
External-memory modelAn input larger than fast internal memoryThe main cost is transfers between slow and fast storage.
File sizeRecorded number of bytes in a fileThe sizeInBytes metadata field supplies the local file weights.
A file-size entry is not a measurement of process RAM.
Final consumerThe last task to use an intermediate fileAfter this task completes, the file has no unfinished users.
Final outputA workflow result retained after processingAn output with no later consumer inside the modeled workflow.
No in-workflow consumer does not mean the result may be deleted immediately.
Forced final consumerA final user determined by dependenciesA consumer that every other consumer must precede.
An earlier position in one chosen order is not a proof that the dependency graph forces that relationship.
Hash mapA key-to-value data structureFind a stored value from a key using hashing.
Expected constant-time lookup is not zero work and depends on the implementation.
HeapA data structure for priority selectionA min-heap keeps a smallest-key item at its root.
Here heap means a priority-queue data structure, not the memory region used for dynamic allocation.
Heterogeneous platformExecution resources have different characteristicsFor example, processors with different speeds or memory capacities.
HeuristicA practical rule without a general optimality guaranteeIt can be useful without always finding the best result.
ImmutableNot modified after creationThe value or structure stays fixed for the relevant computation.
A frozenset is immutable, but the surrounding algorithm can still update other state.
Incremental priority maintenanceUpdate scores only when their inputs changeKeep scores current without evaluating every score from scratch.
This core mechanism has prior art in the XLA source snapshots.
Incremental topological orderingMaintain an order while edges are addedAn algorithm updates the graph’s ordering after dependency changes.
Do not use a total bound across insertions as the cost of one static workflow sort.
IndegreeNumber of incoming edgesThe number of immediate prerequisites not yet removed during Kahn’s algorithm.
Indegree is not the number of files used by the task.
InductionA proof from a base case and a preserved stepShow the claim initially, then show one further step cannot break it.
InvariantA property that remains true while the algorithm runsThe proof identifies what every iteration must preserve.
Kahn’s algorithmSource-removal topological sortingRepeatedly select a vertex with no unfinished prerequisites.
A valid order does not imply minimum storage. A priority queue also has costs that plain FIFO Kahn does not.
Linear extensionA total order compatible with a partial orderIn this setting, another way to describe a valid topological order.
Live-out valueA result that must survive beyond the computationIts storage is still required outside the scheduled computation.
LocalityKeep computation close to the data it usesCan reduce transfers or improve reuse.
A locality improvement may introduce scheduling overhead or imbalance.
MakespanTime until the workflow finishesThe elapsed duration of completing the scheduled application.
Makespan is not the CPU time spent deciding the schedule.
MetadataInformation describing the tasks and dataIdentifiers, dependencies, sizes and counters rather than the image contents.
MontageAstronomical image mosaicking toolkitCombines images using steps such as reprojection, background correction and coaddition.
NetworkXPython graph libraryProvides graph algorithms and graph data structures.
NoveltyA demonstrable difference from the closest prior workThe exact contribution, not just a new title or application label.
OptimalityBeing best under a specified objective and modelA stronger claim than validity or agreement with one policy.
An optimum under one buffer model may not be an optimum under another execution model.
Order equivalenceProduce the same complete task orderHere, identical eligibility, ready scores and tie-breaking yield the same selected sequence.
Both producing valid orders is not sufficient to establish equality of orders.
Ordering timeTime spent constructing the task orderThe primary performance metric of the proposed experiment.
No full Montage ordering-time improvement has been established in the retained synthetic results.
Parallel executionSeveral tasks execute at the same timeRequires reasoning about overlapping execution and shared resources.
The local proofs assume sequential completions; they do not establish parallel safety.
Partial orderAn ordering relation that need not compare every pairDependencies constrain some task pairs while leaving others unordered.
Peak memoryThe largest memory amount at any instantA maximum, not the time average.
Preserving the same order under the same accounting model preserves the modeled peak.
Pearce–KellyDynamic topological ordering by Pearce and KellyA practical method for repairing affected parts of an order after an edge insertion.
PegasusWorkflow Management SystemA system for planning and executing dependent tasks.
Precedence-maximal consumerA consumer that cannot reach another consumer of the same fileA task that could remain last among the file’s users.
“Maximal” does not mean largest ID, longest runtime, or maximum number of successors.
PredecessorAn immediate prerequisiteA vertex with an edge into the current vertex.
An ancestor may be several edges earlier; a predecessor here means one edge earlier.
PreprocessingPreparation done before the main ordering loopBuilding groups, indexes, certificates or other method-specific state.
A counter reduction may save loop operations but lose overall because preparation costs more.
Priority queueA collection ordered by a keySelect the item with the best current priority rather than the oldest arrival.
ProducerThe task that creates a file or bufferThe computation that makes an intermediate result available.
Production costBytes created by a taskA fixed negative contribution to the local priority score.
This is a byte count, not the task’s CPU execution time.
QueueA first-in-first-out collectionAdd an item at one end and remove the oldest item at the other.
ReachabilityExistence of a directed pathu can reach v when a sequence of directed edges leads from u to v.
A search that stops early has not proved a path absent.
Ready setTasks eligible to be selected nextUnfinished tasks whose immediate prerequisites have all finished.
Ready-score equivalenceEqual scores for every eligible taskThe invariant needed by the local exact-order proof.
Do not silently strengthen this theorem to equality of every counter or blocked-task score.
Record labelsE…, S…, D…, M…, R…, P…Local identifiers used to connect sources, families and teaching examples.
They are not published algorithm names or scores of evidence quality.
Reference countingTracking unfinished consumersKeep the number of unfinished tasks that still need each file or buffer.
A reduced priority counter is not necessarily safe to use as a physical file-deletion counter.
Release creditBytes a ready task can make releasableThe size of a file whose sole unfinished consumer is the selected task.
Credit becomes meaningful only under the stated file-lifetime and execution model.
ReplayProcess a recorded workflow through a modelSimulate task completion and update the associated metadata.
A replay proves or measures only the behavior captured by its model.
ReproducibilityOther people can repeat the stated procedureRequires inputs, versions, code, settings and measurement details.
Retained-file bytesSum of the sizes of files currently kept by the modelA modeled data-retention quantity, not a physical RAM measurement.
Reverse postorderDFS finish order read backwardA topological order of a DAG can be obtained this way.
RuntimeTime an operation or program takesIts exact meaning depends on what is being timed.
Read the metric definition: scheduling time, application time and code execution time are not interchangeable.
Saturated counterA counter intentionally stopped at a terminal valueHere, stop decrementing a priority-only counter once it reaches one.
It no longer equals the full outstanding-use count after its final user completes. Do not use it for general deletion accounting.
Scheduling overheadWork spent deciding and maintaining a scheduleTime spent managing the computation rather than doing its application work.
Search budgetA limit on a defined search operationThe teaching code limits edge inspections using B.
The edge budget does not bound sorting, allocation, bookkeeping or all preparation time.
Serverless executionProvider-managed execution of functionsApplications submit invocations without directly managing the underlying servers.
Servers still exist. Dispatch and data-transfer overhead remain relevant.
SpanA non-owning view of a contiguous rangeRefer to elements without copying them.
The referenced storage must remain alive and stable.
StackA last-in-first-out collectionRemove the item most recently added.
Stale queue entryAn entry carrying an outdated priority versionAn earlier heap entry left behind when a newer priority is inserted.
Stale entries still consume memory and removal time.
Streaming modelProcess input through limited passes and storageA different access model from holding the full graph in memory.
SuccessorAn immediate dependentA vertex reached by one outgoing edge.
Synthetic testAn artificially constructed inputUsed to exercise specific structures and edge cases.
Passing synthetic correctness tests is not a measured speedup on real Montage traces.
TaskA unit of workflow computationA processing step that consumes inputs and may create outputs.
TaskInsightScheduling study in the retained comparisonInvestigates performance effects such as task and data locality.
TaskiterTask-graph reuse technique for iterative computationsThe cited 2022 task-runtime work reuses task structures across iterations.
This name here refers to the cited runtime research, not similarly named agent software.
Tie-breakingA fixed rule for equal prioritiesChoose consistently when several eligible tasks have the same score.
Changing ties can change the order even when all scores are otherwise identical.
Topological orderA dependency-respecting vertex orderEvery prerequisite appears before its dependent.
A valid order need not match the reference policy’s order.
TraceA recorded execution or its metadataInformation describing the tasks, files or behavior of a workflow run.
Upward rankHEFT task priority based on downstream workCombines estimated computation cost with downstream communication and work.
It is not the released-byte score used by the local reference.
VertexA graph nodeOne item represented in a graph.
WfCommonsWorkflow research framework and data collectionProvides recorded workflow instances and tools for analyzing them.
WfFormatWorkflow metadata schemaDefines the structure of task, file and execution records.
WfInstancesRepository of workflow execution instancesA collection within WfCommons.
WorkflowTasks connected by dependenciesA collection of processing tasks and the relationships required between them.
LATTICELATTICE, formerly DAN-SchedulerA revised research compiler pipeline; see version 3 metadata and its earlier title under record E34.
