# Application evidence and verification

Reviewed 15 October 2026.

## Evidence rules

The application profiles distinguish a documented implementation, a research evaluation, a related application, and a local teaching extension. The existence of an implementation does not prove a speedup. A paper's reported result is not an independently reproduced result.

The closest verified named applications include Django Media.merge through Python TopologicalSorter, Django migration DFS, Abseil GraphCycles with an explicit Pearce–Kelly citation, Linux lockdep BFS routines, LLVM's Tarjan SCC utility, Ninja's critical-path priority machinery, Graphviz tred, XLA list memory scheduling, and Pegasus workflow cleanup. Official documentation and source code establish these mechanisms at the locators provided in applications/data.json.

PHEFT's full text describes simulated application-shaped workloads. It is not treated as a real deployment of stock HEFT. The embedded image and video scheduling paper is marked abstract-only. LRC is a research prototype in Spark, not the standard policy of all Spark installations.

A historical or specialist method retains its own research application and original sources in the context panel. Its linked prerequisite simulation does not establish deployment of that exact variant. No product adoption was established for the local consumer-grouping, consumer-reduction, sort-or-scan or bounded-search refinements.

## Local checks

* 23 application profiles map to all 23 teaching engines.
* 58 selectable research entries receive qualified application context.
* 31 primary source references supply inspected locators, support and limitations. These are not 31 research papers.
* 16 new named-input scenarios are hand-authored teaching adaptations.
* 33 application-specific checks passed, including independent file-lifetime arithmetic and retained-file integrity.
* 126 browser checks passed in headless Chromium, including all application profiles and research routes, saved comparison reopening, and mobile layouts.
* The retained engine's independent finite test suite passed 8,494 cases after adding the new inputs.

The simulation engine, research method dataset, reviewed source dataset, and core Python method implementation match the input package byte for byte. The display layer was changed to wrap long task labels and to distinguish call edges and lock-acquisition relations from task prerequisites.

These checks do not constitute formal verification, a full reproduction of the named software, a statistical performance study, or a novelty certification. External videos were not watched or playback-tested during this update. External source availability can change. The main HTML and teaching simulations work offline; original source pages require internet.

## Reproducing the checks

From the package root:

```text
python tests/applications/verify_examples.py
python tests/applications/test_interface.py
python tests/simulations/validate_algorithms.py
```

The browser check requires Playwright and Chromium. The general independent algorithm checks require Python, Node.js and NetworkX. The optional retained-byte comparison in verify_examples.py refers to the original supplied ZIP; omit that final integrity section on a machine without the original ZIP. The actual teaching simulations require only a browser.

Exact check results are under tests/applications and tests/simulations. The current update did not run a real Montage workflow or quantify a production-system speedup.
